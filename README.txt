عيادات د. محمد هلال — Laravel 11 / Filament 3

التشغيل المحلي:
1. composer install
2. npm ci && npm run build
3. انسخ .env.example إلى .env واضبط APP_URL وقاعدة البيانات ثم php artisan key:generate
4. php artisan migrate --seed
5. php artisan storage:link
6. php artisan clinic:create-admin your-email@example.com (كلمة المرور تُطلب بشكل مخفي؛ لا يوجد حساب افتراضي)
7. php artisan serve
لوحة الإدارة: /codeAiAdminDash

الفروع:
main: الموقع والثيمان ولوحة إدارة المحتوى وSEO؛ الحجز يجهز طلب واتساب ولا يحفظ موعدًا.
codex/full-system: نفس الموقع بالإضافة للموديولز المحلية المفعلة. طلبات الحجز تُسجل بحالة طلب جديد تحتاج تأكيد العيادة.
بعد الانتقال للنظام الكامل: composer install ثم php artisan migrate. الانتقال في Git لا ينفذ تغييرات قاعدة البيانات تلقائيًا.
تحسينات المحتوى والثيمات المشتركة تدخل main أولًا ثم تُدمج في codex/full-system.
لا تُرجع migrations عند الانتقال للأساسي؛ احتفظ بقاعدة النظام الكامل ونسختها الاحتياطية.
التكاملات الخارجية معطلة افتراضيًا وتحتاج إعدادات وموافقة مستقلة قبل تشغيلها.

الاختبارات:
php artisan test --compact
npm run test:e2e
إطار E2E هو e2e + @e2e-dev/web مثل aldiwan-web، مع اختبارات متصفح حتمية دون استدعاء نماذج AI.
تستخدم اختبارات المتصفح SQLite ومجلد تخزين مؤقتين، وحسابات وهمية داخل بيئة testing فقط.
تقارير المتصفح والصور وملفات التتبع في .e2e/، وهي مستثناة من Git.
تحتاج Chromium محليًا متوافقًا مع playwright-core الخاص بإطار E2E.

مراجعة المحتوى:
الثيم الافتراضي helal_classic؛ الثيم الثاني helal_modern بنفس الهوية.
المحرر يحفظ مسودات مع معاينة موقعة، والنشر يفعّل الثيم ويحفظ إصدارًا للرجوع.
قوائم الخدمات والفروع والفيديوهات والتقييمات والمقالات تدار من صفحاتها، وتُطبق تغييراتها حسب حالة النشر/التفعيل.
المقالات المبدئية غير منشورة حتى مراجعتها طبيًا. التقييمات مقتطفات ثابتة دون مزامنة Google.
أرقام التواصل والعناوين والبيانات الطبية تحتاج مراجعة العيادة قبل الإطلاق. لا توجد أسعار أو أوقات متاحة افتراضية.
صور الخدمات الحالية توضيحية مولدة، وليست صورًا فعلية للعيادة.

الموقع متعدد الصفحات:
/ الرئيسية، /about-us التعريف، /services الخدمات وتفاصيلها، /patient-journey رحلة المريضة،
/gallery الفيديوهات، /blog المقالات، /branches الفروع وتفاصيلها، /frequently-asked-questions الأسئلة،
/contact-us التواصل، /appointment طلب الموعد. الصفحات الإضافية تُنشأ من «صفحات الموقع».
قوائم الهيدر والفوتر من «قوائم الموقع». الحفظ في الصفحات والقوائم وSEO مسودة؛ النشر من استوديو الموقع.
اختاري الصفحة داخل الاستوديو لتعديل محتوى أقسامها. ترتيب أقسام الصفحة وإضافتها وإزالتها من نموذج الصفحة.
الأقسام المشتركة لها نفس المحتوى بين الصفحات؛ حذف قسم من ترتيب صفحة لا يحذفه من الصفحات الأخرى.
الروابط الأساسية لقوائم الخدمات والمقالات والفروع ثابتة. تعديل الروابط الأخرى المنشورة ينشئ تحويل 301 تلقائيًا.
المقالات المستقبلية مخفية حتى تاريخ النشر. أسماء الكاتب والمراجع والمصادر ومواعيد الفروع تُدخل من بيانات فعلية فقط.
تظهر الخدمات على صفحة الفرع عند اختيارها صراحة في نموذج الفرع؛ لا نفترض تقديم جميع الخدمات في كل فرع.
البيانات المنظمة تُولّد تلقائيًا من المحتوى الظاهر؛ بيانات الفيديو تحتاج تاريخ نشر فعلي قبل إخراج VideoObject.

قياس الجودة والترقية:
npm run audit:seo
node scripts/verify-upgrade.mjs ../helal-clinic-full-system
Lighthouse مثبت محليًا ومقفل الإصدار. الفحص يستخدم قاعدة مؤقتة ويمنع الشبكات الخارجية في المتصفح.
يمكن تحديد CHROME_PATH لمسار Chromium إذا لم يكن المتصفح المثبت في موقع Playwright المعتاد.
تقارير SEO والأداء والصور في .e2e/audits/ ونتيجة الترقية في .e2e/upgrade.json.
قياسات Lighthouse محلية بمحاكاة موبايل، وليست بيانات المستخدمين الفعلية أو ضمان ترتيب في البحث.

عند الإطلاق بإذن منفصل:
اضبط APP_URL للدومين HTTPS النهائي، وراجع روابط canonical والمحتوى وأرقام التواصل والخدمات الفعلية بكل فرع.
أدخل قيمة content فقط لكود google-site-verification من إعدادات SEO، ثم تحقق من الملكية في Google Search Console
وأرسل رابط /sitemap.xml. هذه الخطوات لا تجري تلقائيًا، ولم يُرسل الموقع لأي خدمة خلال الاختبارات.
تعليمات robots الأساسية تلقائية؛ محرر Robots يضيف تعليمات إضافية دون إنشاء ملف يتجاوز حماية الإدارة والمعاينات.
إعدادات ضغط الملفات وتخزينها المؤقت في public/.htaccess تخص Apache؛ اضبط المقابل إذا كان الخادم Nginx.

النشر التلقائي على Namecheap:
الإعداد والخطوات في docs/namecheap-deployment.txt. ملف .github/workflows/deploy.yml يختبر ويبني main.
النشر متوقف افتراضيًا، ولا يعمل إلا بعد ضبط Repository Variable باسم DEPLOY_ENABLED إلى true.
الحزم المقفلة تحتاج PHP 8.3؛ اختَرها للدومين في cPanel قبل أول نشر.
