# دليل أرشفة موقع عيادات د. محمد هلال — جوجل وبينج

تاريخ مراجعة الدليل والتوثيق الرسمي: 2026-10-23.

## نتيجة التجهيز المحلي

اتراجعوا 22 رابطًا عامًا منشورًا: 10 صفحات أساسية، 3 خدمات، 3 فروع، و6 مقالات. كل الروابط رجعت 200، ولها عنوان ورابط أساسي مطابق، ولا تحمل noindex. خريطة الموقع شاملة الأنواع دي. اتضاف اختبار يشمل أيضًا صفحة عامة جديدة للتأكد إن التغطية مش قائمة ثابتة.

نجح 15 اختبارًا و395 تأكيدًا لتغطية الصفحات وخريطة الموقع وrobots والإعدادات والمعاينة. تحذيرات PDO القديمة لم تمنع النجاح. [تقرير الفحص المحلي لكل رابط](seo/local-indexing-audit.json).

الفحص محلي فقط: لم يتم نشر التعديلات على السيرفر، أو تسجيل الدخول لحسابات البحث، أو إثبات فهرسة فعلية. الصفحات الخاصة بالإدارة والمرضى والمعاينة والمسودات خارج نطاق الأرشفة العامة.

## 1. قبل إضافة الموقع

بعد نشر النسخة المعتمدة على النطاق الحقيقي، استخدم عنوان الموقع النهائي بـ HTTPS في كل الخطوات؛ لا تستخدم localhost أو رابط معاينة. لا نفترض أن نسخة السيرفر مطابقة للمحلي قبل فحصها.

من لوحة التحكم راجع:

- الصفحات والمقالات المطلوبة منشورة، والخدمات والفروع فعالة.
- إعداد robots لكل صفحة عامة هو index,follow، والرابط الأساسي ليس رابط صفحة مختلفة.
- إعدادات SEO ← تفعيل Sitemap، وتفعيل تضمين الرئيسية والخدمات والمقالات والفروع والصفحات الأخرى.
- لا توجد قاعدة إضافية في robots تمنع الصفحات العامة مثل Disallow: /.

افتح `/robots.txt` و`/sitemap.xml` على النطاق الحقيقي. لازم خريطة الموقع تعرض روابط النطاق النهائي، وليس localhost أو نطاق تجربة، وتفتح الصفحات بدون تسجيل دخول. لو ظهرت خريطة رئيسية تحتوي خرائط فرعية، ده طبيعي: قدم الخريطة الرئيسية فقط.

كل صفحة عامة تنشرها مستقبلًا تدخل الخريطة تلقائيًا حسب إعدادات الإدارة؛ مش محتاج تنسخ روابطها يدويًا داخل XML. لا تضف نسخ المعاينة أو الروابط المكررة. [توثيق خرائط جوجل](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## 2. إثبات ملكية جوجل

1. افتح [Google Search Console](https://search.google.com/search-console/) بحسابك.
2. لو الموقع مضاف وملكيته مؤكدة بالفعل، اختاره بدل إنشاء نسخة أخرى.
3. لو جديد، اختر Add property. خيار Domain يغطي نسخ النطاق ويحتاج إثبات DNS: اكتب النطاق بدون https أو مسار، وانسخ سجل TXT الذي يظهر لك.
4. أضف سجل TXT في إعدادات DNS عند مزود النطاق بالقيمة كما هي، واحفظه، ثم ارجع واضغط Verify بعد انتشار السجل. لا تحذف سجلات موجودة.
5. بديلًا لو لا تملك DNS: اختر URL prefix واكتب عنوان HTTPS النهائي كاملًا، ثم HTML tag.
6. انسخ قيمة content من وسم google-site-verification فقط إلى حقل «كود التحقق من Google Search Console» في إعدادات SEO بالموقع. احفظ وانشر التغيير أولًا، ثم اضغط Verify.
7. احتفظ بسجل/وسم التحقق بعد نجاحه؛ لا يُحذف عند اكتمال الإضافة.

[طرق إثبات ملكية جوجل الرسمية](https://support.google.com/webmasters/answer/9008080?hl=en). كتابة الكود في اللوحة لا تُرسل الصفحات تلقائيًا إلى حسابك.

## 3. إرسال كل الصفحات إلى جوجل

1. داخل الموقع الصحيح في Search Console، افتح Sitemaps.
2. في Add a new sitemap أدخل `sitemap.xml`، أو رابط الخريطة الكامل إذا كانت الواجهة تطلبه.
3. اضغط Submit، ثم افتح نتيجة الخريطة وراجع أن الحالة ناجحة وأن الروابط تم اكتشافها.
4. لو Cannot fetch، تحقق من الرابط ووصول الخريطة على النطاق الحقيقي أولًا؛ لا تعالجها بإضافة localhost.

الخريطة هي الوسيلة لإخبار جوجل بمجموعة الروابط. اكتشاف الروابط ليس معناه فهرستها أو ضمان ترتيبها. [إرسال الخرائط](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

للصفحات المهمة الجديدة: ضع الرابط الكامل في URL Inspection، ثم Test live URL، وراجع السماح بالفهرسة والرابط الأساسي. لو الصفحة سليمة ومش مفهرسة، اضغط Request indexing. ابدأ بالرئيسية والخدمات والمقالات، واستخدم قائمة آخر الدليل للمتابعة. الطلب الفردي له حدود؛ لو وصلت للحد، انتظر بدل تكرار الطلب. تكرار طلب نفس الرابط لا يسرّع زحفه. [طلب إعادة الزحف](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)، [فحص الرابط](https://support.google.com/webmasters/answer/9012289?hl=en).

## 4. إضافة بينج

1. افتح [Bing Webmaster Tools](https://www.bing.com/webmasters/) وسجّل الدخول.
2. لو الموقع متحقق في جوجل، اختر Import from Google Search Console، وراجع الحساب والموقع والصلاحيات المعروضة قبل الموافقة، ثم اختر الموقع الصحيح.
3. أو اختر Add site يدويًا واكتب عنوان الموقع النهائي. اختر وسيلة التحقق التي يعرضها بينج.
4. لو اخترت HTML meta tag، انسخ قيمة content لوسم msvalidate.01 فقط إلى «كود التحقق من Bing» في إعدادات SEO، واحفظ وانشر ثم اضغط Verify في بينج.
5. من Sitemaps راجع هل الخريطة استوردت بالفعل. لو موجودة فلا تكررها؛ لو مش موجودة اختر Submit sitemaps وأدخل رابط `/sitemap.xml` الكامل على نطاقك.
6. راجع حالة المعالجة والروابط المكتشفة. استخدم URL Inspection ثم Live URL للرابط الذي تريد فحصه، وراجع حالة Bing Index. لو أتاح الحساب طلب الفهرسة/إرسال الرابط، استخدمه للصفحات الجديدة المهمة.

[إضافة وإثبات موقع في بينج](https://www.bing.com/webmasters/help/add-and-verify-site-12184f8b)، [إرسال الخريطة](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed)، [فحص رابط في بينج](https://www.bing.com/webmasters/help/URL-Inspection-55a30305). أسماء بعض الأزرار ممكن تختلف حسب لغة الحساب وتحديث الواجهة.

## 5. المتابعة ومعالجة الروابط التي لم تُفهرس

في جوجل افتح Page indexing، واختَر خريطة الموقع لتتابع المجموعة المطلوبة. لفهم رابط بعينه استخدم URL Inspection؛ نتيجة الاختبار المباشر تبين أهلية النسخة الحالية، وليس أنها موجودة فعلًا في الفهرس.

| النتيجة | الخطوة التالية |
| --- | --- |
| Indexed / URL is on Google | سجّل نجاح الفهرسة؛ الظهور في كل بحث أو ترتيب محدد مش مضمون. |
| Discovered أو Crawled — currently not indexed | راجع المحتوى وأصالته وفائدته والروابط الداخلية، ثم تابع التقرير؛ ليست دائمًا مشكلة تقنية. |
| Blocked by robots.txt | راجع القواعد التي تمنع الصفحة العامة. |
| Excluded by noindex | عدّل إعداد الصفحة العامة المقصودة، ثم انشر وافحصها مجددًا. |
| Duplicate / alternate canonical | افحص الرابط الأساسي؛ قد تكون نسخة أخرى من نفس المحتوى هي المختارة. |
| 404 أو Redirect | قدم الرابط النهائي الصحيح، ولا تطلب فهرسة عنوان محذوف. |
| Server error أو 403 | يلزم فحص الوصول والاستضافة على السيرفر بإذن منفصل. |

بعد إصلاح السبب استخدم الاختبار المباشر ثم طلب الفهرسة عند ملاءمته. راجع النتيجة بعد أيام، وتابع دوريًا بدل انتظار فهرسة فورية. [تفسير تقرير فهرسة جوجل](https://support.google.com/webmasters/answer/7440203?hl=en).
